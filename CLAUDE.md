# Tasmi AI — notes for Claude Code

A phone web app that listens to Hamza's Quran tasmi (hifz recitation), stops him on a wrong or skipped word and says
the right word, then keeps listening. Live at https://hamzakalolwala.github.io/Tasmi-AI/ (served from `gh-pages`;
`main` holds the source and tests). Open in Chrome.

History: v2 used the HisnLabs Tajweed v2 model (in-browser ONNX) for tajweed checks; Hamza asked to remove it (too much
latency and errors on device). It lives in git history before the "Remove the tajweed model" commit.

## How it works
- Listening: the browser's Web Speech API (`ar-SA`), ONE `continuous=true` session with interim results for the whole
  recitation (`makeListener` in `site/app.js`) — never restart per phrase: every start() beeps on Android and loses the
  words said meanwhile (v8 and earlier did that: 26 starts per page). Each final result index is passed on once;
  text Android repeats from earlier finals is cut off (`fresh`). Chrome ending the session (long silence, network) →
  restart with backoff (no-speech is not a failure); after 8 failures it stops with a note (network / mic busy /
  blocked); after 40 s with nothing heard it pauses (`QUIET`) instead of beeping on. A 12 s watchdog replaces a
  recogniser stuck mid-phrase. Words left interim when a session ends are judged as final.
  A stop bumps an epoch so late results from before the stop are ignored. Screen wake lock while
  listening; pauses when the page is hidden and resumes when visible. `say()` uses a token so a stop during the spoken
  word keeps the mic off, and waits 0.4 s after the voice before listening again.
- `site/recite.js` — pure word engine (runs in node):
  - `norm` spelling skeleton (no harakat, one alef form, ة→ه, hamza seats, no long alef after the first letter);
    `same` allows 1 slipped letter (2 for words of 10+ letters) — يعلمون/يعملون is a mistake. A held madd (الرحيييم)
    and doubled و/ي collapse; 2-letter words may differ only by a sounds-alike letter (س/ص/ث…; never ق/ك, ع/ا).
  - `prep` cleans what the recogniser wrote: digits → number words, fillers (آآ، امم) dropped, a lone و/ف/ب joined to
    the next word. `align` lets one heard word match two merged tokens (وماأدراك); `dropRepeats` drops 2–5 words said
    twice in a row unless the passage itself repeats them.
  - `tokens` one token per spoken word (a mushaf word may be 2 spoken words: يَٰٓأَيُّهَا = يا أيها); huroof
    muqatta'at are free (may be said as letter names, or not recognised at all).
  - `assess` aligns heard words to the passage from `pos`, allowing a start up to the ayah start (min 6 words) back,
    never ahead — so skipped words are missing, and restarting an ayah after a correction is fine.
  - `decide`: stop on the first wrong/skipped word — on interim results once 3 later words were heard correctly
    (and never for a skipped 1–2 letter word), on a final result immediately; app.js also waits until an interim
    mistake has held for 0.8 s (`HOLD`), because Chrome rewrites its guesses; unmatched words at the end of a final phrase = wrong next word
    unless they repeat recent words. Otherwise commit and move `pos` on. Words before `pos` are never re-judged
    (`res.pos`): going back over them can't stop on them, `pos` never moves back, and app.js only marks words from
    `pos` on — so a mistake stays a mistake (shown amber "corrected", still counted).
  - `withoutPreamble` / `isPreamble`: basmala, isti'adha, "sadaqallahul azim" are ignored (not in al-Fatiha, where
    the basmala is ayah 1).
- `site/app.js` — UI: "Listen by" safha / ruba / nisf / para / one ayah / ayah range (Madani 604-page mushaf,
  `site/divisions.json` from quran-meta via `scripts/divisions.mjs`; ruba = ¼ para = 2 rub' al-hizb, nisf = ½ para);
  passages may cross surahs (`S` = ayat with `sn`/`an`). On a mistake: card + speechSynthesis (ar-SA) with the
  recogniser stopped, then it restarts by itself. Self-check mode needs no mic. `?test=1` exposes `window.__app`.
- `site/words/N.json` — per ayah `{d: display words (Tanzil Uthmani), i: imla'i spelling per word (string, or array
  when it splits)}`, generated by `scripts/words.py` from quran-transcript + quran-json.
- Cache busting: bump `V` in index.html (`TASMI_V`, and the `?v=` on the script tags) on every deploy.

## Tests (59, all passing)
`node --test test/*.test.js`. `recite.test.js` is plain node (incl. stress over all 114 surahs, and every ayah of the Quran recited correctly must never stop — run it after any `norm`/`prep` change). `app.test.js` uses
Playwright + Chrome with a fake SpeechRecognition that emits interim words then a final phrase like Chrome does
(finds Playwright and Chrome itself; set `PLAYWRIGHT` / `CHROME` to override). Includes error/backoff, duplicate
finals, end-without-final, screen-off, failed loads. `sim.test.js` simulates a real reciter against a desktop- and an
Android-like recogniser (continuous sessions, silence timeout, Android repeating earlier finals, start() counted as a
beep): whole page → 1 mic start; mistakes never erased; progress never back; quiet → pauses.
Noise stress harness (simulated recogniser noise over all surahs; not in the repo): see the PR description.

## Android app (`android/`, see android/README.md)
Hamza installs the APK: https://github.com/hamzakalolwala/Tasmi-AI/releases/download/app/TasmiAI.apk — built by
`.github/workflows/android.yml` on every push touching `site/` or `android/`. It bundles `site/` in a WebView;
`site/native.js` swaps Chrome's speech APIs for Android's (`Listener.java`: recogniser restarted after every phrase with
the beep muted; native TTS). App-specific notes in app.js: `window.TasmiNative`.

## Deploy
Copy `site/` to the root of the `gh-pages` branch (delete files no longer in `site/`) and push; Pages rebuilds in ~1 min.
